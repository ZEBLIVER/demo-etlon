# ТВ-меню: демо личного кабинета Etlon Coffee

Кликабельный прототип по ТЗ «ТВ-меню: как работает система» (версия v3). Бэкенда нет: данные замоканы и живут в браузере
(`localStorage`). Макет сделан в первую очередь под телефон (управляющий меняет меню с него), на ноутбуке тоже работает.

**Стек:** Vite · React 18 · TypeScript (strict) · Tailwind · Radix UI · Zustand · React Router · date-fns · lucide-react · Inter.

## Запуск

```bash
npm install
npm run dev      # http://127.0.0.1:5173
npm run build    # проверка типов + сборка
```

## Сценарий показа (7 шагов)

1. **Телефон, управляющий** (кнопка «Управляющий» на входе): «Мои кофейни», три точки. Прямой URL чужой точки или `/users` даёт «Нет доступа».
2. **Литейный → ТВ 1**: превью текущего меню, статус, версия, время связи. Ниже доступные варианты с превью (текущий отмечен).
3. **Выбрать другой → «Применить»** (кнопка закреплена внизу экрана): степпер **Отправлено → Обновляется → На экране**. Старое меню на экране до последнего шага. «История» фиксирует смену.
4. **Заглушка плеера**: на странице экрана «Открыть заглушку плеера» (`/liteyny/1`) в соседней вкладке. Плеер сам отчитывается и подхватывает новое меню, статус в кабинете живой.
5. **Админ**: дашборд (плитки, распределение статусов, «Требуют внимания», журнал). Кофейни: код для ссылки, «Добавить экран» с номером и моделью, новая ссылка `etlonmenu.ru/<код>/<номер>`; пока ссылку не открыли, статус «Ещё не подключён», а плеер показывает заглушку.
6. **Раздел «Меню»** (отдельной медиатеки нет): «Загрузить» нескольких файлов (до 10 МБ, JPG/WEBP/MP4/WEBM) с названием и ориентацией для каждого, отказ с причиной, защита от дублей. Файл + название + ориентация = вариант. Стандартные доступны всем ТВ своей ориентации, особые (прайс Брусники и Лета) назначаются выбранным. Правка варианта (название или замена файла) предупреждает «показывается на N экранах».
7. **Управляющий сам** добавляет ТВ в своей кофейне, удаляет его и перевыпускает ссылку.

## Что в ТЗ и как это сделано в макете

- **Ссылка телевизора** `https://etlonmenu.ru/<код кофейни>/<номер ТВ>`: не секретная. Перевыпуск (админ везде, управляющий в своих кофейнях) выдаёт телевизору новый номер и новый адрес, старая ссылка перестаёт работать. В ТЗ это противоречит фразе «код и номер после создания не меняют», в макете выбран такой способ. В демо заглушка плеера открывается по тому же пути на локальном сервере.
- **Роли:** управляющий выбирает меню из готового и сам создаёт/удаляет телевизоры и перевыпускает ссылки в своих кофейнях. Файлы и варианты ведёт только офис. Права проверяются в мок-API (403), а не скрытием кнопок.
- **Вход:** «Доступ выдаёт головной офис», блок после 5 неудач на 15 минут, смена пароля, отключение учётки закрывает сессию.
- **Статусы:** «На экране», «Обновляется», «Отстаёт» (6 интервалов), «Нет связи» (3 интервала, красный днём и серый ночью 23:00–07:00), «Ошибка», «Ещё не подключён».
- **Варианты:** версии, без файла сохранить нельзя, показываемый удалить нельзя, убранный из доступных остаётся на экране.
- **Кофейни** архивируются, экраны удаляются с подтверждением, у экрана номер, ориентация, модель (Samsung PMF/DBE), комментарий.
- **Журнал** админа с фильтрами по дате, человеку, кофейне и типу.

## Устройство

```
src/
  api/          мок-API (login, getLocations, setCurrentVariant, uploadVariant, …): Promise + задержка 300–600 мс, права внутри, ошибки 403/409
  mocks/        сид-данные
  store/        zustand + localStorage, синхронизация между вкладками, пинги экранов
  lib/          типы, computeStatus, isAvailable, ссылки
  components/   ui, MenuPreview, VariantPreview, PlayerStub, StatusBadge, ScreenCard, Layout …
  pages/        по странице на роут, PlayerPage — заглушка плеера
  routes.tsx    роутинг и защита по ролям
```

Для полноценной системы: функции `src/api/index.ts` заменяются на REST, типы из `src/lib/types.ts` становятся моделью данных,
`computeStatus` и `isAvailable` переезжают на сервер, `PlayerPage` заменяется настоящим плеером (пиксель-пинг, JSONP, AppCache по результатам тестов панелей).
